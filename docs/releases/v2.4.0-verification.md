# v2.4.0 verification coverage and known limits

Documentation addendum draft — 2026-11-11. This note describes the release
candidate being prepared in [#531](https://github.com/PiesP/xcom-enhanced-gallery/issues/531).
The issue's final handoff must identify the protected source commit, build inputs,
all six asset hashes, and final candidate checks before this text is attached to
a public release. No release has been published from this draft.

- Executed locally on the preparation branch: the maintained `verify:full` gate
  passed all 10 tasks with 2,076 covered unit tests, 78 userscript E2E tests
  (Chromium plus Firefox/WebKit smoke), six extension artifact E2E tests, five
  installed Firefox 160 Linux tests, and 218 portable Windows harness contracts.
  The source-bound v2.3.10-to-v2.4.0 upgrade-input parser passed nine focused
  tests after that full run. These are fixture, portable, and local browser
  checks; the final source and distributable still require their own handoff.
- Prior feature evidence remains at [#525](https://github.com/PiesP/xcom-enhanced-gallery/pull/525),
  [#507](https://github.com/PiesP/xcom-enhanced-gallery/pull/507),
  [#508](https://github.com/PiesP/xcom-enhanced-gallery/issues/508),
  [#509](https://github.com/PiesP/xcom-enhanced-gallery/issues/509), and
  [#519](https://github.com/PiesP/xcom-enhanced-gallery/pull/519). It covers
  earlier source and browser identities. The final handoff must state which
  behavior is reusable and which changed build or release input needs a new run.
- Unverified until the final handoff: final candidate installed Windows behavior,
  the v2.3.10-to-v2.4.0 manual upgrade, authenticated live X, Safari runtime,
  Android, the full declared browser-version range, store submission, and
  automatic userscript update discovery. The unsuccessful or partial historical
  attempts remain unsuccessful or partial.

The current declared userscript floors are Chrome/Edge 157, Firefox 159, and
Safari 27.2; the temporary Firefox extension floor is 159. The public stable
channel records for [Chrome 157](https://chromereleases.googleblog.com/2026/11/stable-channel-update-for-desktop.html),
[Firefox 159](https://developer.mozilla.org/en-US/docs/Mozilla/Firefox/Releases/159),
and [Safari 27.2](https://webkit.org/blog/18515/webkit-features-for-safari-27-2/)
confirm availability, not product acceptance. Android remains outside the
desktop support scope.

Numeric attachment ordinals need reliable source-position data; an unknown
partial-DOM position uses a nonnumeric `source-16hex` fallback. Browser or other
extension arbitration can change requested native filenames, and userscript
managers do not universally expose the final basename. Correct ZIP names remain
associated with their bytes; concurrent already-owned Blob paths do not promise
physical member enumeration order. The [#520](https://github.com/PiesP/xcom-enhanced-gallery/issues/520)
reporter's original archive was not reproduced by a live save.

Userscripts whose header still pins a download version need one manual update
from the public Latest asset. Unpacked Chromium and temporary Firefox extensions
require manual replacement; automatic discovery was not tested. To roll back,
reinstall the original v2.3.10 release files in the same browser profile and
reload the installation, backing up settings first. The generated
`release-bundle/RELEASE_NOTES.md` does not append this coverage note. The release
owner must attach the final reviewed text at publication and read back the
release body without changing its assets or tag.
