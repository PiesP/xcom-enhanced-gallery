# Gallery video loading and playback

The clicked/current item and keyboard-focused item attach their video source immediately. Other videos attach their source once when a shared viewport observer reports them within one viewport of the visible area. This margin is a geometric expansion of the viewport, independent of the current item's index and the image `preloadCount` setting. Source attachment remains in place after scrolling away. An unadmitted video has no `src` and uses `preload="none"`; an admitted video uses `preload="metadata"`. Preload is only a browser hint, so request suppression depends on absent `src`. The existing visibility observer continues to pause and mute a video outside the viewport and restore its prior state on re-entry.

The gallery reserves the logical media width and height before the video is fetched. A same-item, HTTPS CDN image may be shown as a poster. Native controls stay visible during deferred loading and after metadata arrives. `data-media-loaded` means geometry metadata is ready, and `data-video-first-frame` means `loadeddata` or cached `readyState >= 2` established frame data. Metadata readiness triggers scroll correction once per media object. Neither state alone proves playback progression.

Playback begins with the preferred display URL. On a native decode or unsupported-source error, the gallery can try at most two other validated MP4 variants from the same `MediaInfo`, once each. Network, abort, stall, user pause, and blocked `play()` events do not switch sources. When a resource timing entry exposes 401 or 403 for the active request, playback does not switch. Cross-origin media timing often hides response status; the media element alone cannot distinguish a hidden HTTP denial from an unsupported-source error. Recovery does not issue a probe request. A playback switch changes only the local video element; current-item identity and single/ZIP download source remain the preferred source. A localized notice identifies the playback substitution.

The source, media object, and mounted element are checked before delayed load/error events can publish state. A new media object resets attempts and readiness; a reorder of the same object retains its source and admission. On close, observer subscriptions and pending resume intent are disposed with the gallery element.

The event distinction and advisory preload behavior follow the [MDN video element reference](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/video). The first-frame test follows [MDN's `loadeddata` definition](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/loadeddata_event); readiness additionally checks `readyState` for cached frames.
